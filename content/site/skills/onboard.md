## When to use it

`$onboard` is for the moment a user does not yet know how to get value from the product. Use it for first-run flows, empty states, setup paths, feature discovery, guided tours, and activation moments.

Reach for it when the product technically works but new users stall, skip setup, stare at an empty screen, or miss the feature that would make the product click.

## How it works

The skill starts with the activation question: what is the "aha moment" users need to reach, and how experienced are they when they arrive?

Then it chooses the smallest useful teaching pattern:

1. **Empty states**. Explain what belongs there, why it matters, and what action starts value.
2. **First-run setup**. Remove optional fields, add smart defaults, and get users to one real success.
3. **Feature discovery**. Teach at the point of use with dismissible hints and progressive disclosure.
4. **Guided tours**. Keep tours short, skippable, replayable, and tied to real workflow.
5. **Measurement**. Check completion, skip rate, time to value, and the first meaningful action.

## Try it

Start with one activation path:

```
$onboard the empty projects dashboard for first-time users
```

Expected output:

- Replaced "No items found" with a value-oriented empty state
- Added primary and secondary start actions
- Added a template path for users who do not know where to begin
- Made guidance dismissible and remembered
- Defined time-to-value and completion checks

## Pitfalls

- **Teaching everything upfront.** Onboarding should get users to value, not turn the product into a manual.
- **Blocking experienced users.** Make guidance skippable unless setup is genuinely required.
- **Repeating dismissed hints.** Track what users have seen and respect it.
- **Disconnecting the tutorial from the product.** Teach real actions in the real interface whenever possible.
