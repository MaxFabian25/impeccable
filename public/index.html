04

Why Impeccable

Seven reasons this is not another AI design wrapper.

Design that knows who it is for.

Most AI UI work starts from a prompt and ends at a plausible mock. Impeccable starts by capturing audience, purpose, register, anti-references, and visual direction in PRODUCT.md and DESIGN.md. Every command reads that context before touching code.

$impeccable teach / $impeccable document / $shape

A landing page and a dashboard should not speak the same language.

Brand surfaces can be expressive, editorial, and memorable. Product surfaces need clarity, density, and stable repetition. Impeccable carries both registers and asks commands like $typeset, $layout, $colorize, and $delight to choose the right one for the job.

Default register lives in PRODUCT.md; individual tasks can override it.

Built to work inside real repositories.

Impeccable is not a detached sketchpad. It reads your source, respects existing tokens and components, scans rendered output, and makes changes in the stack you already use. It is meant for daily work on production code, not one-off mock generation.

Source-aware commands, detector checks, browser inspection, and focused diffs.

Design where Codex already edits.

The useful loop is not canvas to handoff to implementation. It is brief, build, inspect, refine, commit. Impeccable fits Codex's local repository workflow: the skills live in the Codex plugin, the commands are typed with $, and the output is code you can test immediately.

Codex plugin source, marketplace metadata, and detector runtime stay in this repo.

Your design system becomes portable context.

$impeccable document writes DESIGN.md in the Google Stitch-compatible shape: colors, typography, elevation, components, and design do's and don'ts. That gives Codex durable visual memory without locking the project into a proprietary tool.

Strategic context in PRODUCT.md; visual context in DESIGN.md.

Block AI slop before it ships.

Run npx impeccable detect src/ on a PR branch and get deterministic findings for purple gradients, nested cards, low contrast, gradient text, tiny body type, and more. No LLM required, no API key, and JSON output is ready for CI gates.

--json / --fast / exit codes for automation.

See the issues on the page.

The visual overlay highlights every detected anti-pattern in place, whether you open it through $critique, the local live server, or the Chrome extension. You do not have to map a terminal report back to the DOM by hand.

Get Started

1Install the skills Recommended

19 commands that steer Codex toward better design in real time. This is the full Impeccable skill bundle for Codex CLI.

$ npx impeccable skills install
Installs the project-local Codex bundle into .codex/.
Then run $impeccable teach to set up your project's design context.
Other install methods
Manual project install
$ cp -R .codex .codex-plugin /path/to/your-project/
Copy both hidden folders into the project root and restart Codex if it is already running.
Download a Codex bundle

2Add the CLI Beta

Scan any file, directory, or live URL for anti-patterns from the terminal. Catches gradient text, AI color palettes, nested cards, low contrast, and 20+ more rules across HTML, CSS, JSX/TSX, Vue, and Svelte. Use it in CI pipelines, pre-commit hooks, or one-off audits to keep AI slop out of production.

$ npm i -g impeccable
Or use npx impeccable detect src/ directly without installing.

Frequently Asked Questions

Where do I put the downloaded files?

The easiest way is npx impeccable skills install, which installs the Codex bundle into your project root.

If you downloaded a ZIP, extract it to the same directory as your package.json or src/ folder. The bundle creates two hidden directories: .codex/ and .codex-plugin/.

Project-local installation keeps the skills under version control and makes the command surface explicit for Codex.

How do I update to the latest version?

Run npx impeccable skills update from your project root. It downloads the latest Codex bundle and preserves any prefix you use.

  • Alternative: re-download the ZIP above and extract it into the project root.
  • Check first: npx impeccable skills check tells you whether an update is available.

Your PRODUCT.md and DESIGN.md context files are never overwritten without an explicit update.

Commands or skills aren't appearing. What do I do?

For commands: Type $ in Codex CLI and look for commands like $audit or $polish. If they do not appear, confirm the files are inside .codex/skills/.

For skills: Skills are applied automatically when relevant. To verify, explicitly mention "use the impeccable skill" in your prompt.

Codex-specific checks:

  • Restart Codex CLI after installing if it was already running.
  • Check the install root: the canonical path is .codex/skills/.
I'm new to Codex CLI. Where do I start?

Skills and commands are intermediate features. If you are just getting started, learn the Codex basics first:

  • Codex CLI: Codex GitHub

Once you are comfortable with the Codex workflow, come back and give Impeccable a try.

Is Impeccable free?

Yes. Everything is Apache 2.0: skills, commands, CLI, and the detection engine. Fully open source, free for everyone.
